Recommendation · Process gap

Catch the build break before it reaches a reviewer.

We do not run any automated checks on PRs in any of our three repos. The recent build incidents are the predictable outcome — not a person, a missing process. A 30-minute GitHub Actions workflow per repo closes the gap, costs effectively nothing, and gives every reviewer a green/red signal before merge.

04 The fix

A phased GitHub Actions rollout

Don't land the perfect workflow on day one. Three phases, each gated by team comfort, each delivering value before the next begins.

Phase 1 · This week
Typecheck + build as a required PR check
Catches the exact failure mode that just bit us. Add one workflow file per repo. ~30 minutes of YAML.
install → tsc --noEmit → build
Runs on every PR to main / develop
Reviewers see a green or red status check
Phase 2 · Week 2–3
Add lint + unit tests
Extend the workflow once Phase 1 is settled. Lint stays required from day one; unit tests start advisory to surface flakes.
yarn lint on all three repos
yarn test:unit on API + Middleware
Parallel jobs — failures don't mask each other
Phase 3 · Week 3+
Branch protection — must pass before merge
Turn the signal into a gate. Once teams are comfortable with the check existing, make it required to merge.
Required status check on main
Concurrency cancel on stale PR pushes
Optional: Dependabot grouped weekly PRs
Phase 1 drop-in · .github/workflows/pr.yml
~25 lines · ready to commit
name: PR Check on: pull_request: branches: [main, develop] concurrency: group: pr-${{ github.head_ref }} cancel-in-progress: true jobs: check: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version-file: '.nvmrc' cache: 'yarn' - run: yarn install --immutable - run: npx tsc --noEmit # typecheck - run: yarn build
05 Three small things first

Prereqs to clear before CI goes green

None of these are blockers. All three can be handled in the same PR that lands the workflow, or just before it.

RTQ-Admin-UI
Resolve duplicate lockfile
Repo carries both yarn.lock and package-lock.json. Delete one (keep yarn). Otherwise cache: 'yarn' is not deterministic.
RTQ-Admin-UI
Bump off Node 16 EOL
Node 16 reached end-of-life September 2023. Worth bumping to Node 20 or 22 in the same window — keep the version pin in .nvmrc.
RTQ-Admin-API
Expect @types/jest tsconfig quirk
Known pre-existing issue. If it surfaces on the first CI run on main, fix it in the same PR that lands the workflow. Don't let it block rollout.
06 Cost of doing nothing vs. cost of CI

The asymmetry isn't close

Steelmanning "don't add CI" honestly. The arguments are real but small and front-loaded. The downsides are the failure mode the team just experienced.

Status quo Cost of doing nothing
×
Recurring incidents — 16–34 build-fix corrections last year alone, spread across 8–11 contributors.
×
No reviewer signal — reviewers cannot tell whether the author ran the build. Subjective trust is not information.
×
Hooks are bypassable — --no-verify, GUI clients, and fresh clones silently skip them. FE has none at all.
×
One broken main blocks a deploy — the cost of a single hour-long block exceeds a full year of CI minutes.
×
Version drift goes unchecked — FE on Node 16, MW on Node 18, BE on Node 22. No fixed-image build to catch divergence.
With CI Cost of GitHub Actions
✓
~30 min of YAML per repo, once. The workflow files are ~25 lines each and are already drafted in the full analysis.
✓
Free on private repos — 2,000–3,000 included minutes per month is well above our PR volume.
✓
Not bypassable — runs server-side on a fixed Ubuntu image with the repo's pinned Node. Same result for every contributor, every PR.
✓
Reviewer-visible — green check next to the PR. Reviewers know the build passed before they open the diff.
✓
Phased — no big bang. Phase 1 lands the win that matters most. Lint, tests, and branch protection follow only when comfort is there.
TL;DR for the team

The recommendation, in one paragraph

Today we have zero automated checks on PRs in any of our three repos. The result is a measured floor of 16 to 34 build-fix corrections in the last year, distributed across roughly 8 to 11 contributors — a process gap, not a person. A 30-minute GitHub Actions workflow per repo closes the gap: install, typecheck, build, as a required check before merge. It is free at our volume, not bypassable like local hooks, and gives every reviewer a green or red signal before they open the diff. The phased rollout — typecheck + build first, then lint + tests, then branch protection — means we get the win that matters in week one without a big-bang change. Recommend we land Phase 1 this sprint.
