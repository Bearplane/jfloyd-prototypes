QP-3963

MyCOA — drop-in "View COAs" embed for merchant product pages

A two-line JavaScript embed that adds a "View COAs" button to any merchant product page. The embed reads from MyCOA and reflects the current assigned COA automatically — no CMS edits required after initial installation. POC: BlackBear (WordPress + Ecwid), Direct-assignment resolution.

📋 Design notes

This mockup shows the merchant-facing UX only — what a shopper sees on a third-party site. Merchant page renders use a deliberately different visual shell (white bg, system font, blue "Add to cart") to make clear which surface belongs to the merchant and which belongs to Qredible. The Qredible embed element (dark "View COAs" button, COA modal/grid, "Powered by Qredible" attribution) is styled with the standard Qredible token set so it is visually distinct inside the merchant page. MyCOA app-side thumbnails appear only in the auto-update flow diagram.

01 — Installation
What the merchant pastes once

No plugin, no API key, no webhook configuration. The embed script resolves the correct COA via MyCOA's Direct-assignment table, keyed to the product page URL or a data-mycoa-sku attribute.

product-page.html (or Ecwid / WooCommerce theme) 
<script src="https://embed.qredible.com/v1/mycoa.js" async></script>
<button data-mycoa-button>View COAs</button>
Paste once. Auto-updates every time you change a COA assignment in MyCOA.

04 — Merchant pitch
Before and after

What changes for the merchant once the embed is in place.

⚠️

Without the embed

Today, every COA update requires several manual steps across systems. The merchant uploads a new COA file, then opens their product CMS, finds each affected product, pastes in the new document URL, and publishes. This sequence repeats for every variant and every new batch — often multiple times a month — and it is straightforward to miss a product, link the wrong file, or let a stale COA remain live while the new one sits in a folder.

For a merchant with a dozen SKUs and quarterly batch cycles, this adds up to several hours of manual administrative work per year, with compliance exposure whenever a step is skipped.

4–6 manual steps per COA update, per product.
✅

With the embed

With the embed installed, the merchant pastes the two-line snippet into their product page template once, at setup time. After that, every COA update requires exactly one action: open MyCOA, upload the new document, and assign it to the relevant product. The embed reads the assignment and updates every page that carries the product automatically, within about sixty seconds, with no CMS access, no re-publishing, and no risk of linking the wrong document.

For BlackBear's WordPress + Ecwid setup, this means the COA link on every product page is always current by the time the new batch ships, without the merchant touching the site at all.

1 action in MyCOA. Every product page updates itself.
05 — Scope
v1 scope and POC
v1 ships against BlackBear's WordPress + Ecwid stack as the proof-of-concept merchant with Direct-assignment resolution (one COA per product, resolved by product ID or page URL). Shared-assignment resolution — where a single COA covers multiple products or SKUs without a per-product mapping — lands in v1.1 as a separate ticket. See QP-3963 for the full requirements and acceptance criteria.
